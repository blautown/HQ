# Specialty: NDIS auditing

Jacob's domain specialty: **NDIS audit readiness**.

Org-stripped. No client data, no registers, no participant files.

## What this is

Practice and process for getting an NDIS provider's documentation, records, and billing trail into a state that can survive audit. The work is readiness and evidence hygiene, not running the provider.

This specialty is the domain. A live org is an *instance* of it. JRBA is instance one — a real project that still needs refining. Founder effort is not centred there. See [`../instances/README.md`](../instances/README.md).

## What usually travels with it

- Role: [Document Manager](../roles/document-manager.md) — librarian over the provider's document subtree.
- Role: [CRM Billing & Recordkeeping Manager](../roles/crm-billing-manager.md) — CRM used as billing and records, not as a contacts directory.
- Connector classes: document-store subtree; billing CRM. Bind the actual org/login only when the shelf asset is born.

## Out of scope here

No folder maps, no named participants, no staff lists, no audit findings from a live org.
